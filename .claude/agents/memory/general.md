# general — role memory (myclaude repo)

- `~/claude-bible` HEAD (`cac8223`) is a local-only commit; `git checkout` of it in a fresh clone of forrestchang/andrej-karpathy-skills fails with "reference is not a tree". Pin karpathy at the upstream tip, never at the local clone's HEAD. (Proved 2026-08-23 by `src update karpathy` failing.)
- The installed `~/.claude` copy can carry hand edits that no repo copy has (`rules/frank/preferences.md` had the no-hard-wrap rule only in `~/.claude`). Before any `sync --force` or migration, run `diff --content custom` and decide per file which side is newer; the direction is not the same for every file. (Proved 2026-08-23: `LESSONS.md` was newer in the repo, `preferences.md` newer in `~/.claude`.)
- `node --test tests/` fails on Node 24 ("Cannot find module .../tests"); use `node --test tests/*.test.js` (`npm test`).
- Run manifest-changing commands (`pick`, `fork`, `unpick`, `accept`) with `MYCLAUDE_CLAUDE_HOME` pointed at an empty scratch dir until install is approved: `unpick` deletes from the claude home, `accept` copies into it, and `fork` copies the INSTALLED copy when one exists (on this machine an older ECC-fork version), not the pinned source. (Proved 2026-09-28 by reading `cmdFork` and `sync --dry-run` on a copy of `~/.claude`: 12 CONFLICT/LOCAL-MODIFIED, all older installed copies.)
- `accept` refuses entries in state MISSING, so it cannot move a pin when the claude home lacks the files. After `git diff --stat <pin>..<head> -- <picked paths>` shows no change, edit `sources.<name>.sha` in `manifest.json` directly. (Proved 2026-09-28: `accept skills/wait-what/` → "is MISSING".)
- A skill with `disable-model-invocation: true` cannot be loaded by another skill or command through the Skill tool; a conductor that needs it reads `~/.claude/skills/<name>/SKILL.md` as a file. (Source: mattpocock/skills@c55ee46 skills/productivity/writing-for-agents/SKILL-MECHANICS.md "Invocation"; applied to `clarify` in product-cycle and improve-codebase-architecture.)
- A headless install test works with `env -i ... HOME=<scratch> claude -p ... --permission-mode bypassPermissions` after copying `~/.claude/.credentials.json` into the scratch `.claude` (delete it afterwards). The Claude CLI itself rewrites `settings.json` `model` (`opus` → `opus[1m]`) and `skills/synced/<id>/.last-complete-round` at session start, so take "before" checksums before the first `claude` run and expect these two changes. (Proved 2026-09-28, docs/verify/install-e2e-2026-09-28.md.)
- After `sync --force` in the same session, a shell `for`/`while` loop was refused with "Contains compound_statement"; one `node -e` command worked. Keep install steps free of shell loops. (Proved 2026-09-28, same report.)
